# Game Daily Generation Contract

> 这是从当前 `AI游戏每日趋势` Scheduled Task 抽离出的、供应商无关的业务契约。目标是让任何模型/Agent/Skill 都能生成与现网下游兼容的 canonical Markdown。

## Mission

每天生成《AI 游戏每日简报》。核心目标是独立、无预设地发现游戏行业真实变化，不为了验证已有观点而筛选证据。

必须主动寻找：
- 反例
- 矛盾信号
- 意外趋势
- 突然爆发的新游戏
- 现象级产品

同时覆盖轻量、中量、重量级游戏以及整体行业变化。

## Source universe

包括但不限于：

游戏平台与生态：
Roblox、Steam、itch.io、Apple App Store、Google Play、微信小游戏、抖音小游戏、TikTok Mini Games、Fortnite/UEFN、Minecraft、Poki、CrazyGames、Newgrounds、Rec Room/Core、Telegram Mini Apps/Games、Discord Activities、LINE。

社区：
X、Reddit、TikTok/抖音、YouTube、Bilibili、小红书、公开开发者社区。

官方与行业：
平台官方公告、工作室博客、GDC、gamescom、可信行业媒体。

研究：
arXiv、ACM、IEEE、AIIDE、FDG、CHI/CHI PLAY、CoG、NeurIPS、ICLR、ICML 等。

## Explosion detection

主动寻找：
- 短时间突然进入榜单
- 并发/下载/销量/讨论急升
- 跨平台外溢
- 被大量模仿
- 形成新题材或新机制语言

如果无法解释爆发原因，明确写“原因暂不确定”，禁止为了形成故事而强行解释。

## Article positioning

- 普通读者第一次看到游戏也能理解
- 开发者能得到趋势信息
- 结论先行
- 简洁
- 可溯源
- 保留讨论空间
- 正常 1500–2500 中文字；变化少时宁可更短

## Fixed structure

```markdown
# AI 游戏每日简报｜YYYY-MM-DD｜Day N：一句话概括当天最重要变化

导语 80–150 字。

## 一、今日核心动态

## 二、平台热榜：大家现在在玩什么

## 三、AI 游戏进展：AI 今天真正改变了什么？

## 四、研究雷达：实验室里在试什么？

## 五、社交讨论：玩家和开发者最近在聊什么？

## 六、今天怎么看？

## 七、今天留一个问题

## 八、来源链接
```

### 今日核心动态

条目数量按信息量决定，不凑数。每项先写事实结论，再解释游戏/机制、重要性、反证或不确定性。不要全部围绕 AI。

### 平台热榜

不机械抄榜。优先呈现有信息量的：
- 现象级/突然爆发
- 小体量或中体量新品
- 长期常青
- 重量级新品

首次提及游戏时：

```markdown
> **玩法说明**
> 1–3 句话说明玩家到底在做什么。
```

首次出现术语时：

```markdown
> **机制说明｜术语**
> 一句话解释。
```

只有有可靠历史快照时才能写具体排名变化。

### AI 游戏进展

严格区分：
- AI-native 玩法/角色/规则/UGC/世界/自动测试
- 仅使用 AI 图片、配音、文案等生产工具

允许结论是“今天没有重要 AI-native 新进展”。

同时跟踪失败、玩家反感、监管/版权、安全、成本和技术限制。

### 研究雷达

每天最多 2–4 项。用普通语言解释研究问题、方法、结果、可能影响、限制。主动寻找暴露技术瓶颈或与主流观点相反的研究。

### 社交讨论

每天 2–4 项。标记：
- 【有公开数据支持】
- 【公开讨论样本】

不得把少数帖子写成全网趋势。呈现主要分歧。

### 今天怎么看

3–5 条，每条使用：
“判断 + 证据 + 反证/保留意见”。

允许互相并存的趋势。

## Evidence / URL rules

生成草稿时同步收集候选来源，但候选来源不能直接视为合格来源。

发送/发布前必须逐条核验：
1. URL 可访问
2. 页面实体匹配
3. 直接支持紧邻事实、数字、日期、排名、玩法或引述
4. 足够具体

能用具体游戏页/公告/论文/帖子时，不得用榜单首页、subreddit 首页、账号主页、搜索页替代。

平台专项：
- Steam：核对 App ID 与标题；销量/更新优先官方永久公告。
- arXiv：核对 paper ID、标题、作者/摘要。
- Roblox：排行榜只支持榜单口径；点名具体体验时尽量使用精确 games/place 页面并核对标题/开发者。
- Reddit/X：具体讨论必须指向具体帖子、评论或线程。
- 一个段落多个独立事实时，分别提供来源。

无法核验时：
- 优先替换为权威直接来源
- 找不到则删除/弱化事实并明确“无法公开核验”
- 绝不猜 App ID、paper ID、post ID 或 URL

## Canonical source layout

最终 Markdown 是 GitHub、Pages、邮件、公众号等渠道的唯一内容源。

正文中的真实 URL 数量必须为 0，所有 URL 只允许出现在最后：
`## 八、来源链接`

正文引用：

```markdown
> **来源引用｜[1][2]**
> Steam 官方公告；Steam 游戏页
```

文末：

```markdown
> **[1] Steam Community 官方公告**
> <https://example.com/...>
```

规则：
- 按正文首次出现顺序连续编号
- 同一 URL 只列一次
- 多处引用复用同一编号
- 不跳号
- 正文每个编号都能在文末找到
- 文末每个编号都有 URL

## Final gate

只有以下全部通过才允许进入 delivery：
- 标题、日期、Day N 正确
- 结构完整
- 正文（来源章节外）URL 数量 = 0
- 引用编号闭合
- 无重复编号
- 无跳号
- 无重复 URL
- 所有 URL 已实际核验
- UTF-8 Markdown 正常
- 事实与来源关系经过检查

任一项失败：先修复，不发布。

## Day N

Day 0 是基线。从 Day 1 起可以写：
- 首次出现
- 连续第 N 天
- 明显升温/降温
- 跨平台出现

但这些判断必须有可验证历史数据。新证据优先，必要时明确写“昨日判断需要修正”。

## Artifact

文件名：
`AI游戏每日简报_YYYY-MM-DD_DayN.md`

H1 与文件名的日期、Day N 必须一致。
